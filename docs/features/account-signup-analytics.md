The conversion changed from a waitlist lead to a first-time Firebase account. The web uses Google; current native source offers Apple and Google. Each client uses Firebase's successful credential result, requires `isNewUser=true` and an allowlisted provider (`google.com`, plus native `apple.com`), and compares the result account with the current account. Local duplicate guards hold IDs in memory only; the event contains only `sign_up` and a bounded `method=google` or `method=apple`. Both providers are enabled in the shared Firebase project `nye-restroom`. Creating a Firebase account on one client does not make that same account new again on the other; matching email alone never triggers automatic account linking.

The website preserves sanitized manual pageviews and private-referrer handling. Reading Auth metadata and delivering Analytics are best effort after successful authentication, so Analytics cannot fail a completed login. Returning or restored logins, canceled/failed requests, legacy email forms and direct thank-you visits do not emit signup. Existing waitlist data and email delivery are retained separately; this migration does not grant newsletter consent.
